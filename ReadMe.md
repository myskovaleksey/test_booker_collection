# API Testing Collection (Restful Booker / Booking API)

Коллекция тестов для автоматизированного тестирования API с использованием **Postman**

## Структура репозитория

* `collection/restful-booker.postman_collection.json` — файл коллекции Postman с запросами и тестами.
* `collection/restful-booker-test.postman_environment.json` — файл переменных окружения (Environment).


---

## Как импортировать коллекцию в Postman

1. Скачайте репозиторий или клонируйте его себе на компьютер.
2. Откройте приложение **Postman**.
3. В левом верхнем углу нажмите кнопку **Import**.
4. Перетащите или выберите файлы из папки `collection/`:
   * Сначала саму коллекцию (`restful-booker.postman_collection.json`).
   * Затем файл окружения (`restful-booker-test.postman_environment.json`).
5. В правом верхнем углу Postman выберите импортированное окружение и приступайте к работе.

## Описание тестовой документации

Вся документация по тестированию (тест-кейсы, результаты и баг-репорты) собрана в единой Google Таблице:
👉 **[Ссылка на проект в Google Sheets](https://docs.google.com/spreadsheets/d/1-61ycI46vf-9uof76h8-3m2nvdGEfCydCYKgcJVM4XU/edit?usp=sharing)**

Таблица разделена на **три основные вкладки**:

### 1. Тест-кейсы (Test Cases)
Содержит подробный набор проверок для всех эндпоинтов сервиса Restful-Booker (`/auth`, `/ping`, `/booking`).
* **Что внутри:** позитивные и негативные сценарии, проверки граничных значений, заголовков и методов авторизации.
* **Как пользоваться:** используется для ручного регрессионного тестирования и как основа для автотестов в Postman.


### 2. Результаты тестирования / Чек-лист (Execution Results)
Вкладка с отчетом о прохождении созданных тест-кейсов.
* **Что внутри:** статусы выполнения (`Passed`, `Failed`, `Blocked`), фактические результаты и связи с дефектами.
* **Как пользоваться:** позволяет оценить текущее качество сборки и процент успешных прохождений (Pass Rate).

### 3. Баг-репорты (Bug Reports)
Список дефектов и несоответствий, обнаруженных во время тестирования API.
* **Что внутри:** подробное описание багов, шаги для воспроизведения, ожидаемый и фактический результат, приоритеты (Severity / Priority).
* **Пример найденного бага:** расхождение фактического кода ответа сервера с ожидаемым (например, на пустой запрос авторизации или метод `ping`).

## Запуск автотестов через Newman и генерация HTML-отчёта

Для автоматического запуска коллекции тестов в консоли используется утилита **Newman** (консольный ранер для Postman).

### 1. Установка зависимостей
Перед первым запуском убедитесь, что у вас установлены Node.js, а затем установите сам Newman и репортер для красивых HTML-отчётов (`htmlextra`):

```bash
# Установка Newman глобально (опционально) или локально в проект
npm install newman --save-dev

# Установка расширенного HTML-репортера
npm install newman-reporter-htmlextra --save-dev

```
### 2. Запуск тестов и генерация отчёта
Выполните следующую команду в корневой директории проекта для запуска коллекции с использованием файлов окружения и генерации HTML-отчёта в папку `report/`:

```bush
newman run collection/restful-booker.postman_collection.json \
  -e collection/restful-booker-test.postman_environment.json \
  -r htmlextra \
  --reporter-htmlextra-export ./report/report.html
  ```
  После выполнения команды в папке проекта автоматически появится папка `report/` с готовым интерактивным файлом `report.html`

  ### 3. Просмотр отчёта
  Вы можете открыть сгенерированный отчёт в браузере прямо из терминала:

  ```bush
  xdg-open report/report.html &
  ```
